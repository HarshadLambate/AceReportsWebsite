Get it on NuGet

See why every .NET test failed, in one HTML file.

Install one NuGet package and every dotnet test run writes a report with the logs, API calls, screenshots and retries behind each result. Works with xUnit, NUnit, MSTest and Reqnroll.

Everything you need to debug a failure, already captured.

You don't add logging code to get a useful report. Ace Reports records what happened while each test ran, and keeps every retry separate.

  • Install and run

    The package wires itself into the build. Run dotnet test and the report appears in TestResults, next to your test binaries.

  • Every API call

    Each HttpClient request is captured with method, URL, bodies, status and duration. Authorization and cookie headers are redacted automatically.

  • Screenshots when a test fails

    Taken automatically from Playwright, Selenium or Puppeteer. Add your own named screenshots at any step with Ace.TakeScreenshot("After login").

  • Retries and flaky tests

    Each attempt keeps its own logs, API calls, error and screenshots. A test that passes after an earlier attempt failed is marked flaky, so it doesn't hide.

  • Step-by-step logs

    Write Ace.Info, Ace.Pass, Ace.Fail or Ace.Debug from anywhere in a test. Each line lands on the test that's running. Reqnroll steps are logged for you.

  • Search, filter and categories

    Filter by status or category, search by test name or argument, and click a bar in the category chart to narrow the table.

  • One file, no server

    Styles, data and screenshots are inside a single HTML file. Email it, attach it to a ticket, or publish it as a CI artifact. It opens in any browser.

  • Light, dark or system theme

    Pick a default with Ace.DarkTheme(), and anyone reading the report can switch.

Your first report in three steps

Ace Reports needs .NET 10. These steps use xUnit; swap the package name for your framework.

  1. Add the package

    In your test project:

    dotnet add package AceReports.Xunit

  2. Run your tests

    From Visual Studio, Rider, or the command line:

    dotnet test

  3. Open the report

    The path is printed at the end of the run:

    TestResults/AceReport_<timestamp>.html

Pick the package for your framework

Every package produces the same report. Each one hooks into its framework in the way that framework expects, so your existing tests don't change.

FrameworkPackageWhat gets recorded
xUnit v3AceReports.XunitFacts and theories with their arguments, [Trait("Category", …)] tags, and retries through xRetry.
NUnit 3.14+ and 4AceReports.NUnit[Test] and [TestCase] values, [Category] tags, and every [Retry] attempt.
MSTest 3.10+ and 4AceReports.MSTest[TestMethod] and [DataRow] values, [TestCategory] tags, and every [Retry] attempt.
Reqnroll 3AceReports.ReqnrollScenarios, features, tags and example rows, with each Given/When/Then step as a log line. Runs on any Reqnroll runner.

Using Reqnroll alongside plain tests? Install AceReports.Reqnroll together with your runner's package. Scenarios get their steps and tags, and nothing is reported twice.

Questions

Is Ace Reports free?

Yes, for any use, including commercial use inside your company. It's source-available under the PolyForm Perimeter License 1.0.1. The one thing it doesn't allow is building a product that competes with Ace Reports.

Do I need a server or a separate tool to view the report?

No. The report is one self-contained HTML file. Open it in any browser, send it to a teammate, or keep it as a build artifact.

Does it work in CI pipelines?

Yes. The report is written to TestResults like any other test output, so you can publish it as an artifact in GitHub Actions, Azure DevOps, GitLab or Jenkins. Set the environment name with ACEREPORTS_ENVIRONMENT or dotnet test -p:AceReportsEnvironment=QA.

Will my passwords or tokens end up in the report?

Authorization, Cookie and Set-Cookie headers are always redacted. Request and response bodies are recorded as sent, so treat the report like a log file. You can turn API capture off with Ace.CaptureHttpTraffic(false).

Can I turn it off for one project?

Add <EnableAceReports>false</EnableAceReports> to that project's .csproj. The package stays installed and your tests run as normal.

Can I use it in a product I sell, or under my own brand?

That needs a commercial license: OEM, white-label and redistribution terms are available. Email lambate05@gmail.com with your company name and how you plan to use it.
